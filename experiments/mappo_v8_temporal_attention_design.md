# v8 方案：面向异步、多跳信息的协同图注意力

状态：2026-10-28 已在 2D 仿真中实现第一组实验（状态证据异步、一跳几何保持 v7 契约），尚未训练，见 [v8 实现说明](mappo_v8_relay_attention_20261028.md)。ROS 消息、地图证据异步、一跳测量延迟仍未实现。基础是 [v7 实现说明](mappo_v7_cooperation_20261027.md)。这里把“转发跳频次数”理解为**转发跳数 hop count**，不是无线电载波跳频次数。

## 1. 要解决的问题与结论

无人机 i 在时刻 t 能直接测到邻机 j 的当前相对位置，同时通过 j 收到远端 k 的较早状态。两者不能当作同一时刻的精确状态。图注意力能依据内容、时间、传输路径学习匹配，但普通 GAT 不会自动知道消息有多旧，也不能凭权重恢复从未收到的真实状态。

方案：显式传递原始观测时间、源标识、序列号和跳数；构造每机独立、异步更新的知识缓存；在注意力相关性之外增加绝对可靠性门控。训练同步模拟这些通信过程，而不是给 Actor 完整全局图后仅加随机噪声。

“相邻信息实时准确”是 v7 仿真的理想观测假设。实机也必须测量时间戳与定位误差；直连消息可能旧，多跳消息也可能较新，所以不做“直连永远可信、多跳一律不可信”的固定分组。

## 2. 三种图分开维护

| 图 | 节点和边 | 可以用于什么 |
|---|---|---|
| 导航图 G_nav,i | 地形可通行节点、真实已观测的可通行边 | 路径与探索价值；未知部分保留未知 |
| 物理通信图 G_radio(t) | 当下可直连的设备和实际无线链路 | 发包、链路约束；转发不能新造物理边 |
| 接收知识图 G_info,i(t) | i 实际收到的邻机/远端状态及其来源、年龄 | 时效注意力、队友意图预测；可以含当前不可直连对象 |

图消息的“融合并再次广播”只代表局部信息逐步传播。动态连通、带宽有限、丢包和设备移动时，不保证每机拥有完整且同步的全局导航图。v8 目标是依据不同的局部知识有效协作。

## 3. 协议与缓存：先使年龄/跳数可观测

每个独立消息/证据条目携带下列字段，而不仅给整个融合包加一个时间戳：

| 字段 | 语义 |
|---|---|
| origin_id, boot_id, seq | 原始产生者、启动会话、递增序列号；三元组用于去重和处理重启 |
| source_stamp | 原始测量时间；每次转发必须保持不变 |
| sender_id, receive_stamp | 本跳发件者、本地接收时间；不覆盖 source_stamp |
| hop_count | 走过的链路数：直达接收为 1，经一个中继为 2；每发送一跳增加 1 |
| payload_type, frame_id | 状态/意图/地图证据/任务等类型与公共坐标系 |
| state, covariance/confidence | 测量、原始不确定性；不能将重复转发当作新独立观测 |
| mission_id, goal_epoch | 任务及滚动目标版本；迟到的旧目标不得覆盖新目标 |
| hop_limit, expires_at | 限制环路/广播风暴和过期使用；expires_at 不因转发重置 |

发送者按预算选择增量；接收端先验证坐标系/任务版本/时间，再去重、融合、排队转发。相同 origin/boot/seq 只计一次证据，记录多条接收路径时可保留质量更好的传输元数据，但不得生成新测量时间。缓存有容量上限；优先淘汰过期条目，再依据任务相关性和年龄压缩。

地图融合须保留每项证据的来源或可审计摘要。静态地形的年龄衰减可比动态邻机状态慢；不能用融合包的新发布时间刷新整个旧地图，也不能平均多个来源时间后宣称所有节点都新。

时钟同步可用 GNSS/PTP 等已有条件，但是否满足精度须实测。跨机年龄用 t_local−source_stamp−估计时钟偏差；把时钟偏差界计入不确定性。不确定源时间的消息标记 time_unknown，并用保守接收年龄/路径延迟上界；未来时间超容差的消息隔离，不简单截成“最新”。

## 4. 时效与跳数注意力

状态条目 e 在 i 的年龄为 Δt_e，跳数为 h_e。可靠性不是跳数的同义词：年龄解释陈旧程度，跳数解释路径累积损失/不确定性，二者分别归一化并做相关性消融，防止重复惩罚。

令消息特征为：

\[
z_e=[x_e,\;\operatorname{TimeEnc}(\Delta t_e),\;\log(1+h_e),
\;\text{type}_e,\;\Sigma_e,\;\text{known masks}_e].
\]

来源 ID 用于缓存与去重，不作为具有固定角色含义的学习 embedding；actor 保持对设备重命名和槽位排列不敏感。可以对新鲜度和任务相关性联合截断为 K 个 token，不能仅按距离删除唯一的远端任务信息。

同一任务相关的自身状态、局部传感器和导航 GAT 表征产生 query。不同类型分别投影 key/value：

\[
\ell_{ie}=\frac{q_i^\top k_e}{\sqrt d}
 -\operatorname{softplus}(a_{\rm type})\frac{\Delta t_e}{\tau_{\rm type}}
 -\operatorname{softplus}(b_{\rm type})\log(1+h_e).
\]

过期、重复、坐标无效或任务版本冲突条目先 hard mask；合法项内 softmax 得到相对相关性 α。再单独计算绝对可靠性：

\[
\rho_e=\mathbf1_{\rm valid}\exp[-\Delta t_e/\tau_{\rm type}
 -\lambda_h(h_e-1)-\lambda_\Sigma\operatorname{tr}(\Sigma_e)],
\quad c_i=\sum_e\alpha_{ie}\rho_e v_e.
\]

上述参数为待调设计参数，不是经过无人机实验验证的数值。ρ 的下限不强行设为正数，且**门控后不再重新归一化为总和 1**；同时输出有效条目数、平均/最大可靠性与缺失标记。所有条目无效时 c_i=0，使用自身观测和记忆，不产生 NaN。

为什么不能仅把年龄减进 softmax？只有一条旧消息时 α 仍为 1；全部消息都旧时相对权重和也仍为 1。绝对门控才表达“没有多少可信信息”。注意力权重也不等于概率意义的测量可信度。

可选短时运动外推 p_hat=p_source+v_source·Δt，同时让协方差随 Δt 增长；超过预测有效窗则标记未知。外推用于策略上下文，不作为精确物理位置。静态地图、动态状态和任务意图分别设衰减/过期规则。

编码器输出进入共享 actor，可加 GRU 维护本机历史：πθ(a_i | o_i,c_i,m_i)。如果加入 GRU，PPO 必须按序列采样，保存 rollout 起点隐藏状态、episode mask 和 burn-in；不能打散时间步后假装记忆一致。本版设计优先无 GRU 时效 attention 做基线，再评估是否需要记忆。

## 5. 协作与安全控制边界

v7 的局部 RNG + 双端 CBF 依赖双方看到一致的新鲜几何。v8 若只让“任务/地图/远端状态消息”异步，而一跳相对测量仍保持该契约，可直接沿用这一几何安全层做第一组实验。

如果一跳几何也延迟/丢失，不能直接套用 v7 的连通证明。第二阶段需设计独立协议：先请求新边、双方确认同一 edge_epoch 和租期、可行性检查后启用，再释放旧边（make-before-break）；同时保持有根路径/无环证明，避免并发换父节点形成环。双方不一致时保留旧的已确认边；保留新旧边会增加约束，也必须检测 CBF 不可行。

对延迟几何按速度界、测量协方差和时钟误差扩张位置集合，用鲁棒距离边界约束实际链路。超时进入明确恢复/任务中止状态；“悬停”不能保证仍连接正在移动的队友或车辆。消息 attention 不承担避碰或连通安全证明。

独立的无线网络层仍需多跳 mesh 或应用层 store-and-forward。应用程序重新发 ROS 话题，不等于电台天然支持 mesh；ROS topic 可达也不证明物理直连。上机前核对伴随计算机、无线链路、路由能力、时钟和坐标基准；当前代码无法证明具体硬件型号的吞吐、射程或端到端时延满足要求。

## 6. 当前 ROS 可复用部分与缺口

[ros_drone_node.py](../src/teamed-planning/scripts/drone/ros_drone_node.py) 已接收其他无人机的图，控制器融合后发布自己的 current_graph，因此有融合图再次传播的基础。`_drone_status_cb` 仅缓存位置，尚未保留原始状态时间/跳数；`_status_loop` 发布本机状态，未建立远端状态转发表。[RobotStatus.msg](../src/teamed-planning/msg/RobotStatus.msg) 虽有 Header，也不能替代转发条目的 origin/seq/source_stamp 契约。

[GraphNode.msg](../src/teamed-planning/msg/GraphNode.msg) 有 last_updated，但缺少每个来源证据的完整转发元数据。[drone_main.py](../src/teamed-planning/scripts/drone/drone_main.py) 的 Python 字典广播含 ground_missions，ROS 包装器没有等价地逐项发布整个字典；因此不能把 Python 仿真的任务转发当作现成的 ROS 能力。

拟修改点为：新 RelayEnvelope/StateEvidence 消息；统一 RelayManager 的去重、源时间、队列、TTL；ROS 收发回调与图转换的 provenance 保留；本地异步缓存；v8 Actor 编码；模拟器事件队列。这里只列接口，不在本次落地。

## 7. 训练必须对应部署的信息条件

每机持有自己的地图和状态缓存。每个有向实际链路维护事件队列，采样发送周期、排队、传输延迟、抖动、丢包、乱序和容量；转发需要新的事件，禁止同一步递归传播到全网。消息只在 receive_time≤当前决策时刻时进入 Actor；未收到过的远端节点不存在。地图融合间隔、更新率、时钟偏差、来源去重与部署实现一致。

集中训练可让 Critic 看集中状态，Actor 的输入仍严格限制为各自接收缓存。PPO 保存动作产生时的缓存编码，训练时不得用后来补齐的缓存重建旧观测。团队奖励基于车辆实际接收的有效地图、当前任务进度和安全/时间成本；重复转发不重复发奖。不因“多发包”或“跳数高”直接奖励，通信成本只有实测/仿真带宽模型建立后才纳入。

课程：v7 理想通信 → 仅任务/地图/远端状态异步 → 带宽与消息乱序 → 一跳测量不确定和链路丢失。最后一阶段须先完成鲁棒安全协议，不能仅增大 dropout 就称作可部署 v8。

## 8. 验证矩阵与可证伪标准

| 组别 | 改动 | 要回答的问题 |
|---|---|---|
| v7 | 无时效 metadata | 基础协作能力 |
| v8-A | 仅年龄，含门控 | 陈旧程度是否带来实际收益 |
| v8-B | 仅跳数，含门控 | 路径信息是否有独立贡献 |
| v8-C | 年龄+跳数，只有 softmax | 全部陈旧时是否错误自信 |
| v8-D | 年龄+跳数+绝对门控+过期 | 完整方案能否减少错误利用陈旧状态 |
| 对照 | 固定衰减加权/均值聚合 | 是否真的需要可学习 attention |

单元/协议测试包括：源时间跨三跳不变；跳数逐跳+1；旧序列号不覆盖新；同源重复证据不加置信度；设备重启；时钟倒跳；全空/全过期/单个旧条目；零延迟退化；乱序、多跳到达时间因果性；图缺失；重新编号。

场景需覆盖远端探索、临时遮挡、队友换位、车辆移动、一个关键中继失联；固定物理轨迹回放先验证元数据，再闭环评估。指标包括任务成图/车辆到达、实际证据 AoI、状态预测误差、断连时间、CBF 不可行/干预、传输字节、算力延迟；至少多个随机种子，报告区间而不是单次最高分。注意力可视化只能辅助诊断。

## 9. 与 vtemp 的接口

v8 只处理当前任务目标。vtemp 加入车辆维护的 `(mission_id, goal_epoch, q, valid_until)`，让同一协作策略分段支持“车辆当前位置→当前临时目标”。缓存中的旧目标不能覆盖新目标；没有新目标确认的无人机继续安全维护原通信职责。切换目标不重置整个任务奖励预算，不产生虚假的路径改善。

完整四页算法报告见项目根目录 [vtemp.tex](../vtemp.tex) 与 [vtemp.pdf](../vtemp.pdf)。
