# vtmp2：部分观测下的世界模型任务选点

本目录仅存放实验说明与记录，算法名称为 **vtmp2**。

## 世界模型决策与任务分工（2026-11-08）

世界模型根据车辆当前实际获得的信息，在约±200m范围内比较候选位置与任务类型。这个范围是候选规划范围，**不是无人机此刻已经扫描出的地图范围**。决策可以要求无人机去补充未知区域的信息，不要求无人车也驶向同一个点。

当前任务分成两种：

- `drive`：世界模型预测驶向候选点的后果；车辆执行该行驶目标，无人机通过原任务广播配合探测。
- `survey`：世界模型预测派无人机探测候选区域的信息收益；只将该点作为无人机任务广播，车辆保持位置。第一版没有“侦察时沿旧路线继续行驶”，因为当前模型输入未编码独立的旧行驶目标，不能引入模型看不到的执行动作。

`planner.py` 使用已训练模型对候选点进行多次随机连续推演：后续步骤使用模型自己的预测状态、地图与隐状态，不读取未来真实观测。评分综合预测任务推进、图信息增量、停滞/CBF事件分数和预测离散程度。`mission.py` 将已知驾驶点、未知驾驶点和未知侦察点一起交给模型评分；空间分层只限制计算量，不用“已有路线优先”覆盖模型决策。选择的是候选集合内预测代价最低的任务，不保证真实环境中的全局最优。

信息收益目前是预测的已接收导航图节点/边数量净增量代理，**不是完整地形覆盖面积**。不能直接把随车辆移动的栅格像素变化当新增探索面积。粒子离散程度和短时事件分数尚未校准成整段可达概率。

`runtime.py` 在当前感知、通信融合之后才更新模型信念和决策。模型预测不会写回车辆融合图，不会把未知点升级为`verified`。无人机的通信/CBF约束与车辆的已知障碍检查仍作用于实际执行。侦察完成仅表示车辆实际收到目标附近的图证据，不表示车已到达或已证明整段可通行。

新入口 `mission_pipeline.py` 支持新数据采集、训练及真实模型闭环运行。它冻结每次运行的源码与配置。**11月7日的旧checkpoint只学过驾驶动作，不能直接用于新增的侦察决策**；新入口加载时会检查任务契约以及训练数据是否同时包含两类动作。

从仓库根目录执行（`RUN`为新的、尚不存在的artifacts子目录；CPU/GPU按环境选择）：

```bash
python -I -B src/teamed-planning/scripts/world_model/mission_pipeline.py \
  --output "$RUN" --train-scenes 32 --val-scenes 8 --workers 6 \
  --max-steps 4000 --epochs 100 --device cuda
```

这是明确标注为`bootstrap_drive_survey`的双任务采集器，随后训练联合预测模型；不能把bootstrap数据采集称为学习策略表现。每场景默认按`min(max_steps, max(600, ceil(3*reference_length+240)))`分配预算，参考路线只用于离线准入和时间预算，不进入选点输入。

另用独立场景运行真正的世界模型任务选点：

```bash
python -I -B src/teamed-planning/scripts/world_model/mission_pipeline.py \
  --output "$EVAL_RUN" --checkpoint "$RUN/training/best.pt" \
  --train-seed 88000 --val-seed 89000 --train-scenes 4 --val-scenes 2 \
  --workers 2 --max-steps 4000 --horizon-steps 8 --particles 4
```

这里train/val只是文件分组，提供checkpoint的运行不会训练模型。`data/*.decisions.json`记录任务类型、选点与模型代价，`collection_manifest.json`记录两类任务步数及侦察期间车辆位移。新数据使用schema 3：动作第三维`+1`为请求10步驾驶，`-1`为请求10步侦察；同坐标切换任务类型也必须切分样本。完成事件按任务解释为车辆到点或收到侦察目标附近证据，均不是任意长时间的最终可达性标签。

训练保留一步预测与KL，增加默认4段自由推演损失。`rollout_validation.json`按1/2/4/8段报告实际时长、误差和不变预测基线。该验证使用记录的动作序列，可能包含目标切换；不能代替固定候选长期推演与独立闭环验证。当前随机障碍数据和二值地图不包含完整的平原/林地语义，学习地形延续规律仍需要相应场景和观测数据。

## 原始驾驶基线与首轮模型

世界模型输入包括车辆收到的融合导航图、车载局部观测、车辆位置/朝向/速度、最终目标、无人机信息年龄和接收状态。`Vtmp2WorldModel.imagine()` 还需要一个外部候选临时目标作为动作，输出预测地图、车辆状态和到达/停滞等结果。它并不直接回归一个新的目标坐标。

原`pipeline.py`及`Vtmp2SubgoalManager`保留为**几何启发式驾驶基线**，不承担新增双任务的世界模型决策。首轮训练产物只验证过预测能力，不能表述为已验证有效的学习型导航策略。冻结 v9 权重仅控制原有无人机策略，不能当作 vtmp2 世界模型权重。以下旧运行规则与记录属于该基线；新任务决策以上文为准。

旧采集器随机取 60/120/200m 目标、固定保持60s。vtmp2 改为：按通信侦查范围生成候选，结合已收到的导航图和本地障碍证据筛选，每个控制周期重新核对现有目标。

## 临时目标的距离

这里的范围指 **以无人车当前所在位置为中心，在通信骨干约束下无人机可以展开侦查的范围**；不是车载8×8m传感窗口，也不是已建图区域。

当前冻结运行配置为3架无人机、95m三维单跳通信距离、15m飞行高度、24×24m单机感知窗口。用感知窗口的内切半径12m，不使用方形角点夸大覆盖。候选规划的每跳预算为：

```text
L = (通信距离 − CBF链路余量) × 部署折扣
R侦查 = sqrt(L² − 高度²) + (无人机数 − 1) × L + 感知窗口半宽
R选点 = min(配置上限, R侦查)
```

无可用无人机，或地空链预算低于飞行高度时，侦查半径为0。默认链路余量0.25m、部署折扣0.85，得到约252.20m；当前配置上限200m，匹配世界模型图输入的±200m范围，所以默认有效选点半径为200m。不能只增大候选上限而不扩大输入范围。

0.85是 vtmp2 新增的规划裕度；它不等于原策略的硬通信阈值。约252m描述允许机群重新展开后的几何包络，并不证明当前机位下每个点都能立即被观测、CBF动作必然可行或地面车辆能够通过。原无人机通信/CBF约束继续约束实际动作。可用机数或通信配置变化时，应更新控制器的 `reconnaissance`；范围收缩后，下个控制周期会撤销超范围目标。

默认 `recon` 模式优先选择有安全接入和已收到图边支撑的有用目标；不足时可以选通信侦查范围内的未知探索点。未知点标为 `unverified`，只表示允许尝试侦查，不会标为可达。局部已知障碍、失效图边和近期失败点会排除候选。没有安全出发方向则保持位置。

## 运行时重选

- 在本轮局部感知、图接收融合完成后选择一次目标；新目标同步进入路径规划及车辆广播。
- 已知阻塞、原已验证路线失去连通性、侦查范围收缩或外部执行失败时立即重选，不等待最短保持时间。
- 临时目标到达阈值为1m。45s既无接近也无新图证据时重选；即使图增长，120s没有接近也会重选。最终目标坐标保持不变。
- 正常重评估间隔5s，最短保持3s，改善阈值2个几何评分单位；这些规则只用于防抖，不能阻止安全失效时换点。
- 失败目标周围5m暂时抑制90s，避免马上重复选中同一坏点。
- `controller.subgoals.request_target((x, y))` 可在运行中请求新临时目标；下个控制周期验证范围和已有障碍证据后采用或拒绝。
- `controller.subgoals.invalidate_target("planner_failed")` 可主动报告执行失败并触发重选。

`target_status` 区分 `verified`（当前证据支持一条路线）、`unverified`（待侦查）和 `hold`（暂无安全候选）。已验证目标失去原路线时必须撤销，不能通过降级成待侦查目标来继续锁定它。

## 采集契约

数据标记为 `algorithm=vtmp2`、`schema_version=2`、`selector_mode=geometric_reconnaissance`。请求动作仍为“目标位置 + 请求10步”，实际执行时长单独记录。每步执行旧缓存动作后，控制器才更新下一步目标；如果目标变化，立即结束旧样本，下一条样本记录新目标，保证一个样本不混用两个目标。

新增 `target_switched`、`switch_reason`、`target_status`。原 `rejection` 标签仍指模拟器无人机 CBF 的 `SafetyTermination`，不能当成地面目标不可达标签。

## 代码位置

实现及依赖清单都在 [src/teamed-planning/scripts/world_model](../../../src/teamed-planning/scripts/world_model/)：

- `data.py`：观测编码与数据采集。
- `model.py`：`Vtmp2WorldModel` 与训练损失；保留 `WorldModel` 导入别名。
- `planner.py`：只读取当前合法观测的多步模型推演与候选评分。
- `mission.py`：驾驶/无人机侦察联合任务选点与重选。
- `mission_pipeline.py`：双任务数据采集、训练和模型闭环执行入口。
- `vtmp2.py`：临时目标候选、证据检查、重选和运行时接口。
- `reconnaissance.py`：通信约束下的侦查范围计算。
- `runtime.py`：冻结控制器的运行时适配，不修改存档源码。
- `feasibility.py`：训练场景的连续物理路径认证和证据存档。
- `train.py`：世界模型监督训练、确定性验证和检查点续训。
- `pipeline.py`：独立后台运行的筛选、采集、训练流程。
- `install_gpu.py`：GPU 版 PyTorch 安装与验证。
- `requirements-gpu.txt`：GPU 环境依赖清单。

安装日志与状态仍写入 [artifacts/world-model-gpu-setup](../../../artifacts/world-model-gpu-setup/)。

## 首轮世界模型训练

正式任务：[vtmp2-world-model-20261107T155931Z](../../../artifacts/vtmp2-world-model-20261107T155931Z/)。目录名称中的时间为UTC。运行状态以该目录的 `status.json` 为准，入口进程 PID 为2083925。

- 32个训练场景（seed82000–82031），8个独立验证场景（seed83000–83007）。沿用100–400m起终点距离的随机森林分布。
- **全部场景先通过物理路径认证，才开始采集。** 认证检查真实起点→参考折线→真实终点的每个连续线段，逐障碍计算精确最短距离，检查世界边界，要求至少1.5m净空。该值匹配冻结车辆控制器；不降低安全距离，不删除障碍来制造可行路径。
- 完整场景和参考路径保存在 `scenes/*.json`；证书、路径长度、最小净空和场景哈希汇总在 `scene_manifest.json`。采集前再次核对哈希并复核几何，确保执行的是经过筛选的同一场景。
- 参考路线和障碍真值仅用于离线场景准入。世界模型和临时目标选择器仍只使用车辆自身观测与实际收到的导航图。
- 6个CPU采集进程，每个场景最多600步。实际选择失败、停滞、CBF终止也保留；存在物理路线并不意味着当前策略必定到达。
- 前4个训练场景、2个验证场景完成后，先进行5轮小样本训练检查，同时继续采集剩余场景。小样本数据为固定快照，输出单独保存在 `bootstrap_training/`，不混作正式成绩。
- 全部采集结束后，在完整训练/验证集上从头训练100轮。GPU为物理编号2的RTX4090D（进程内 `cuda:0`）；batch32、序列窗口16、AdamW学习率3e-4、梯度裁剪1。
- 同一场景不跨训练/验证集；同时检查种子和不含split的几何哈希。序列不跨episode，尾部padding被mask。验证使用确定性预测，报告状态、地图、事件和时长误差，并保留“状态/地图不变”的基线。
- 每轮原子保存 `training/latest.pt`、按验证损失选择的 `training/best.pt`，包含优化器、随机数状态、源码/数据哈希，可严格续训。`training/metrics.jsonl` 记录真实优化步数和梯度，`training/dataset_statistics.json` 记录事件正例比例。
- 后台进程不依赖编辑器会话，代码快照在 `runtime_sources/world_model/`，日志为 `pipeline.log`。训练不会自动把新权重部署到目标选择器。
