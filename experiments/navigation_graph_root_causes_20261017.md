# 导航图断连原因审计（2026-10-17）

结论：这批样本有明确的观测到拓扑图转换瓶颈，不能把断连主要归因为训练不足。12 次失败均严格复现原奖励、覆盖面积、车辆距离与终点距离；所有生产源文件和模型 SHA256 与原评估核对一致。此次只增加诊断脚本和报告，未修改训练或导航实现。

## 直接证据

全部 12 次的实际送达原始观测，离线累计后都包含起点到目标的安全连通路径。5 次内部断图样本中，每架无人机最终持有的图也都不连通；将三架最终图重新统一融合仍不连通。因而不能仅解释为地面接收延迟或地面融合把现成完整路径丢掉。无人机端图已含邻机融合结果，不能据此宣称已完全排除无人机间融合问题。

|---|---|---:|---:|---|
|final / 30000|是|541|531|否|
|final / 30003|是|449|441|是|
|best / 30002|是|392|356|否|
|best / 30004|是|536|515|否|
|best / 30005|是|314|302|是|

720 = 240 步 × 3 架无人机。无节点采样不代表图被清空，也不代表没有更新已有节点的观测计数。补边只是离线诊断，不保证车辆在原时间预算内成功。补边后仍断开的样本，说明在当前15米连边上限下，仅修复既有节点之间的连接仍不够，需要补充/调整节点或更合适的路径表示。

## 1. 采样区域与传感器尺寸不匹配（直接复现）

实际视野为 12×12 像素、分辨率2米，即24×24米。DroneController 配置节点间距10米、最大边长15米；SkeletonGraphBuilder 把最大边长的一半7.5米当作每侧裁剪边界，最终安全采样区域只有9×9米。有效像素中心只剩相对坐标 ±1、±3米的4×4网格，最远两点距离约8.49米，小于10米节点间距。因此每机每帧最多采样一个节点，初始图不可能直接形成边。

对同一批真实输入重算采样，保留骨架清理而只取消区域裁剪时，空采样帧明显减少；这确证采样损失来自裁剪，不能直接当成可部署修复（视野边缘安全、跨帧连接仍需验证）。

|模型/场景|原空采样|仅取消裁剪|仅取消骨架清理|两者均取消|
|---|---:|---:|---:|---:|
|final / 30000|541|10|528|0|
|final / 30003|449|8|415|0|
|best / 30002|392|36|323|0|
|best / 30004|536|21|405|0|
|best / 30005|314|12|299|0|

代码：`drone/drone_main.py:84`，`drone/skeleton_graph_builder.py:117`、`:235`、`:432`、`:462`。骨架清理反复剥除所有端点，并非仅删除短枝，属于次要采样损失来源；本批消融显示裁剪影响更大。

## 2. 旧节点之间不补边（代码与运行记录双重确认）

update_graph 只有产生新节点才调用增量连边，增量函数也仅从新节点出发。新候选落到既有节点3米内会直接跳过。已有两个分量后来同时被观测到安全连接时，没有持续修补旧节点连接的步骤。

12 次回放共捕获 141 个事件：同一无人机当帧已有两个不同连通分量的节点，距离≤15米、通过当前语义图连边检查，但更新后仍未连接。其中 137 个也通过真实几何1.5米净空校验。这些是重复观测事件数，不是独立断点数量，也不全是任务关键断点。

独立最小复现：空旷12×12语义图内放置两个相距6米的旧节点；重复观测更新后仍是2节点、0边。代码：`drone/skeleton_graph_builder.py:266`、`:293`、`:525`。

## 3. 跨视野连接没有从累计观测中恢复

现有融合通过空间近邻合并节点并复制已有边，并不根据累计自由空间生成缺失的跨分量通道。仅靠空间去重，不能连接相距超过合并阈值、但中间已被观测的图分量。5次明确断图的离线候选修补线段均位于已送达的自由空间观测内；真实几何也已验证安全。

因此“原始自由空间证据足够、拓扑图却不够”的问题已经证实。具体缺口不应全部归咎于旧边刷新：例如 final/30003 没捕获同机同时可见的旧节点漏边事件，却可用累计观测支持的短边补通，提示跨帧/跨机连接也需要处理。

## 4. 训练反馈没有直接约束最终图完整性（结构性风险）

当前奖励是导航代价下降/100 + 0.6×新增观测面积/400。代价项能间接奖励改善图，但未设置最终任务图连通性或缺口闭合的直接约束；面积项不要求生成节点或边。final/30000 中面积奖励21.402、导航代价奖励−2.118，总奖励仍19.284，而最终图不连通。不能凭这一个数证明奖励必然造成失败，但它说明高奖励不保证图合格。

Actor 的12维候选特征包含位置、任务距离、局部节点数和置信度等，没有显式连通分量、关键缺口或候选动作的连通增益。best 模型按验证奖励选取，而非任务图连通率。因此修复建图以后，再改指标、观测及奖励比直接延长训练更有依据。代码：`simulator/mappo_experiment.py:38`、`drone/mappo.py:162`、`simulator/train_mappo.py:151`。

## 方法与边界

回放记录了真正进入奖励证据账本的(source, frame)，仅使用这些送达帧的原始占据图重建自由空间。0.5米世界网格中的每个点按对应原始2米像素查询；跨帧取曾观测为空闲的并集。真实障碍物仅用于离线排除不安全网格，净空1.5米外另加半格对角线裕量，采用4邻接连通，禁止对角穿角。真值不补充未观测区域，不输入控制器或训练。

这是一种离线信息充分性检查：不是已实现的在线建图器，也不是对噪声传感器的通用融合方案；原2米观测的离散化误差仍存在。结果说明最终观测中已有可行通路，不证明策略在足够早的时刻完成了观测。未测量首次成图时间，未执行修复图后的车辆反事实导航，未宣称5次失败全部由某一代码缺陷独立造成。

建议顺序：适配采样与边界处理 → 在观测支持下补旧边及跨分量连接 → 用固定原始观测验证任务图完整性 → 加任务图连通率、首次连通时间、绕行比作为验证指标 → 再重训。
